CODING 01

Repair a Function Under a Contract Change

Spec evolution
Prompt
You are fixing a Python function used by an API client.

Current code:
```python
def normalize_tags(tags):
    return sorted(set(t.strip().lower() for t in tags if t))
```

Original behavior was merely "remove duplicates." The production contract is now more specific and supersedes that vague requirement:

1. Preserve the order of the FIRST valid occurrence.
2. Trim surrounding whitespace.
3. Compare tags case-insensitively for deduplication.
4. Preserve the spelling/case of the first valid occurrence AFTER trimming.
5. Ignore None values and values that become empty after trimming.
6. Input may be any iterable, including a generator; do not iterate it twice.
7. Return a list.
8. Do not use third-party packages.

Required examples:
normalize_tags(["  Alpha ", "beta", "ALPHA", None, " ", "Beta ", "Gamma"]) == ["Alpha", "beta", "Gamma"]
normalize_tags(x for x in ["X", "x", " Y "]) == ["X", "Y"]

Return:
- the corrected function,
- a short explanation of what was wrong with the original,
- four assert-based tests including both required examples plus two edge cases.

Do not sort the result.
Expected Result
A correct implementation is equivalent to: 
def normalize_tags(tags):
    seen = set()
    out = []
    for value in tags:
        if value is None:
            continue
        cleaned = value.strip()
        if not cleaned:
            continue
        key = cleaned.casefold()
        if key not in seen:
            seen.add(key)
            out.append(cleaned)
    return out
  • Must preserve first-occurrence order.
  • Must preserve first valid occurrence's case.
  • Must handle generators in one pass.
  • Must ignore whitespace-only strings and None.
  • casefold() or equivalent case-insensitive keying is acceptable.
CODING 02

SQL: Latest Successful Backup Per Server

SQL semantics
Prompt
You have these tables:

servers(id, name, environment, retired)
backups(id, server_id, started_at, completed_at, status, bytes)

Write ONE PostgreSQL query that returns exactly one row per active production server, including servers that have never had a successful backup.

Required output columns:
server_name
last_success_at
last_success_bytes

Rules:
- Include only servers where environment = 'prod' and retired = false.
- A successful backup is status = 'success' AND completed_at IS NOT NULL.
- "Latest" means greatest completed_at, not greatest started_at or backup id.
- If two successful backups for the same server have identical completed_at, use the greater backup id as the tie-breaker.
- Servers with no successful backup must still appear with NULL last_success_at and NULL last_success_bytes.
- Do not use a correlated scalar subquery twice to fetch the timestamp and bytes separately.

After the SQL, explain in 3-5 sentences why your query preserves servers with no successful backup and how it handles the tie.
Expected Result
Acceptable PostgreSQL patterns include LEFT JOIN LATERAL, DISTINCT ON in a subquery, or a window-function subquery. One concise answer: 
SELECT s.name AS server_name,
       b.completed_at AS last_success_at,
       b.bytes AS last_success_bytes
FROM servers s
LEFT JOIN LATERAL (
    SELECT completed_at, bytes
    FROM backups
    WHERE server_id = s.id
      AND status = 'success'
      AND completed_at IS NOT NULL
    ORDER BY completed_at DESC, id DESC
    LIMIT 1
) b ON true
WHERE s.environment = 'prod'
  AND s.retired = false
ORDER BY s.name;
  • Must use completed_at for recency.
  • Must tie-break with larger id.
  • Must use a LEFT-preserving strategy so no-backup servers remain.

Evidence-based debugging
Prompt
A Python service intermittently fails while parsing an API response.

Code:
```python
def get_primary_ip(payload):

    interfaces = payload["interfaces"]

```

Observed successful payload:
```json
{"interfaces":{"eth0":{"ip":"10.0.0.4","primary":true}}}
```

Observed failing payload from production:
```json
{"interfaces":[{"name":"eth0","ip":"10.0.0.4","primary":true},{"name":"eth1","ip":"10.0.0.5","primary":false}]}
```

Stack trace:
```text
AttributeError: 'list' object has no attribute 'items'
  at get_primary_ip line 4
```

A teammate writes: "The API contract says dictionary, so production must have corrupted JSON. Add a retry."

Your task:
1. Diagnose the immediate failure from the evidence supplied.
2. Rewrite get_primary_ip so it safely supports BOTH demonstrated payload shapes while preserving current behavior.
3. Raise ValueError("invalid interfaces shape") for any other interfaces type.
4. Return None if no item is primary.
5. Give three tests: dictionary shape, list shape, and invalid shape.
6. In one sentence, explain why a retry alone does not address the demonstrated bug.
Expected Result
The demonstrated failure is a schema-shape mismatch: production supplied a list, while the function assumes a dict and calls .items(). 
def get_primary_ip(payload):

    if isinstance(interfaces, dict):
        values = interfaces.values()
    elif isinstance(interfaces, list):

    else:
        raise ValueError("invalid interfaces shape")

        if data.get("primary"):
            return data["ip"]
    return None

  • No need to use the list's name field for the requested behavior.
